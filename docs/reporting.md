# Suite reports (BATCH-009, first slice)

Explicitly capture each test with Domstride::Report.capture(directory: "tmp/domstride-suite", name: "Create expense", html: true) { ... }. Default html false. Sessions created inside that fiber-local scope use its private case directory and HTML policy, taking precedence over recording environment or explicit recording options. Existing sessions are not reassigned. Close/reset sessions inside the block. Case status comes from the block completing or raising; explicit status= supports skipped/pending/unknown. For frameworks that consume exceptions internally, set the actual framework status yourself. This is not yet an automatic RSpec/Minitest/Cucumber formatter. An exception is re-raised without serializing its message. Case names and raw HTML can contain sensitive information; export locally only.

Run bundle exec domstride report tmp/domstride-suite to create report.html (0600, no overwrite). Select a case by name/status, select its recording, navigate snapshots with existing before/after and reversible layout. Multiple recording workers per case are supported. No recordings is a valid case. Command success is not test success. Case directory and file symlinks rejected. Limits: 100 cases, 200 recordings, 32 MiB aggregate unescaped trace JSON, existing per-recording bounds. Report export does not scan arbitrary directories recursively or execute application code. No automatic test assertion mapping yet; suite-level browser UI tests and framework adapters remain follow-up.
